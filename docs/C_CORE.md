# Portable C core (M6), gridmon-core 0.6.0

One C99 float32 implementation of the frozen methods (docs/DSP_SPEC.md, docs/FEATURES.md, the rules
of baseline_rules.py and the GBM-embedded walker of docs/MODEL_FORMAT.md) for the PC (SIL), TI C2000
(monitor-only module, M7) and the browser (WebAssembly, M8). It reproduces the Python reference; it
does not change or improve any method. Simulation-only: monitor output, never a control or
protection input. Evidence: reports/m6_sil.json [SIM].

## 2. API (gridmon.h)
```c
gm_ctx_t ctx;                 /* caller-provided; 15,816 B on hosts (7,908 16-bit words); no other state */
gm_result_t res;
gm_init(&ctx);                /* once: zeroes every buffer, sets the magic */
gm_process_record(&ctx, x, 5000, 0x1p-10f, &res);   /* x: int16 planar [ab | bc | ca], 3 x 5000 at 5 kHz */
/* res.rule_label / res.rule_reason / res.onset_estimate_s  -> PRIMARY output (rules, D-050)
 * res.gbm_label / res.gbm_proba[7]                          -> ADVISORY output (log only, never act on it)
 * res.features[37] + res.feature_valid[37], res.aux[8] + res.aux_valid[8], res.flags, res.status */
```
- `gm_status_t`: GM_OK 0, GM_ERR_NULL 1, GM_ERR_NOT_INIT 2 (no gm_init), GM_ERR_LENGTH 3 (n_per_ch != 5000),
  GM_ERR_LSB 4 (lsb <= 0). On error the result is still written (status set, label normal, gbm_label -1).
- `flags`: JUMP_DETECTED 0x1, DF_END_FALLBACK 0x2 (whole END jump-masked), ROCOF_END_NONE 0x4 (rocof_end
  invalid, D-051), NO_SIGNAL 0x8 (v1_ref = 0), THD_INVALID 0x10 (zero fundamental in a THD window).
- Labels are class indices (gridmon.CLASSES order: normal, sag_bal, sag_unbal, swell, phase_jump,
  freq_event, oscillation); reasons are baseline_rules.REASONS codes 0..7.
- `uint32_t gm_ctx_words(void)` = sizeof(gm_ctx_t) x CHAR_BIT / 16 (16-bit words on every target; no size_t
  in the API). `gm_version()` = "gridmon-core 0.6.0 (model gbm_embedded seed0 sha256 e25501759a5f84fe;
  tables <GM_TABLES_ID>; gbm on|off)".
- Build options: `GM_ENABLE_GBM` (default 1; 0 removes the walker and the 13.6 KB model), `GM_REPORT_NAN`
  (default 0: invalid features are 0.0f with feature_valid = 0; 1 on host SIL builds: NaN like Python),
  `GM_TRACES` (host only: `gm_process_record_traces` also fills gm_traces_t with every golden-vector array),
  math hooks `GM_SINF GM_COSF GM_ATAN2F GM_SQRTF GM_DIVF GM_FLOORF GM_EXPF GM_FABSF` (default: libm float
  functions and `/`). TMU note: C28x TMU intrinsics (`__sin`, `__cos`, `__atan2`) work in per-unit angles
  (radians / 2 pi) — a firmware mapping must scale the argument/result (e.g. `#define GM_SINF(x)
  __sin((x) * GM_K_INV_2PI)`), and equivalence must then be re-shown (L3).

## 3. Processing order (one record, whole record in the caller's buffer)
1. Urms(1/2) (99 windows x 3 channels) -> urms features.
2. Phasors m = 19..999: 3 x 100-term DFT, V1/V2; stores |V1| and angle V1 (1000 floats each), REF |V2|/|V1|
   and V2 (131 each); running OBS min/max (first argmin m* with V2(m*)), END sums.
3. Frequency: df_raw then the 20-term moving average IN PLACE (descending m), f_ref = median over REF,
   J over OBS (max, first argmax, first lobe), jump mask, masked df_end/df_max/aux_t_freq, ROCOF (100 taps)
   over unmasked OBS -> rocof_max, t_rocof_02, rocof_end (+ validity).
4. Unbalance: v1_ref (median), v1_*_rel, u2_*, V2 de-rotated by f_ref -> V2d_ref medians -> rho.
5. DSOGI-PLL over 5,000 samples (needs f_ref) -> dfpll_max, t_fpll_05.
6. Envelope (needs v1_ref, f_ref): 98 block means, detrend (running median of <= 21), 2 x 5 x 28 spectral
   bins -> env_* features, gaps, aux_t_osc_*.
7. THD (10 windows x 3 channels x 15 bins).
8. Rules (PRIMARY), then the GBM walker on the feature vector with the validity mapping (ADVISORY).

## 4. Memory and constants
| item | bytes (host) | note |
|---|---|---|
| gm_ctx_t | 15,816 | 3 x 1000 phasor-rate floats (|V1|, angle, df), 4 x 131 REF floats, 4 x 100 envelope floats, 28 spectrum floats; budget 32 KB |
| record buffer | 30,000 | caller's (int16 3 x 5000), read only |
| gm_result_t | 348 | caller's |
| stack | < 1 KB | largest frames: GBM x[37]+raw/e[7], THD/phasor locals |
| DSP tables (const) | 5,400 | twiddles exp(-j 2 pi i/100) and /500, ROCOF kernel, Hann(50) |
| GBM model (const) | 13,972 | c/generated (14 B/node), omitted with GM_ENABLE_GBM=0 |

Constants (D-054): scripts/gen_c_tables.py computes every constant in float64 from the reference
functions (gridmon.dsp.phasor/freq/pll/envelope/thd, configs/baseline.yaml, configs/frozen_methods.yaml)
and writes float32 hexadecimal literals (`0x1.921fb6p+2f`), so every target uses bit-identical constants and
nothing is computed with libm at run time. Comparison thresholds use directed rounding (D-058): for a
float32 x, `x < t` (float64 t) equals `x < up32(t)`, `x > t` equals `x > down32(t)`, `x >= t` equals
`x >= up32(t)`. `gen_c_tables.py --check` (tested) proves the committed tables are current; the table
SHA-256 is in gm_tables.h and its first 16 hex digits in gm_version().

## 5. C28x portability (checked by tests/test_c_portability.py)
- float32 only (no `double` token; `-Wdouble-promotion -Wfloat-conversion -Werror`), every floating literal
  has an `f` suffix; `-ffp-contract=off` on hosts (no fused multiply-add; C28x FPU32 has none either).
- No malloc, no stdio/stdlib/string calls, no VLAs (`-Wvla`), no recursion (call graph checked), no static
  or global mutable state (only `const` tables), no unions or float pointer casts.
- Types: int16_t/int32_t/uint16_t/uint32_t only (no plain int/char/int8_t/uint8_t; the one `char` is the
  version string); indices that can exceed 32767 are int32_t; no sizeof in the API except gm_ctx_words.
- Cross compiles with the same flags: ILP32 (`-m32` via `zig cc -target x86-linux-musl`: the VM's gcc has
  no 32-bit libc headers) and a 16-bit-int target (`zig cc -target msp430-freestanding-none`, stub math.h).
  CHAR_BIT = 16 itself is only exercised by the TI compiler (M7, L2).

## 6. Build (scripts/build_c.py -> build/, git-ignored)
Compiler: `$CC`, else cc/gcc/clang, else `python -m pip install ziglang` and `python -m ziglang cc`.
Flags: `-std=c99 -O2 -Wall -Wextra -Wpedantic -Wconversion -Wdouble-promotion -Wfloat-conversion -Wvla
-Werror -ffp-contract=off`. Outputs: `build/libgridmon_sil.so` (ctypes; GM_TRACES, GM_REPORT_NAN=1),
`build/gm_cli`, `build/gm_cli_asan` (-fsanitize=address,undefined, no recovery), compile checks of the
GM_ENABLE_GBM=0 / no-traces / traces variants. CLI: `build/gm_cli [--lsb PU] [--features] records.bin`
(int16 native-endian, planar 3 x 5000 per record) -> one JSON line per record; `--version`.

## 7. SIL (scripts/run_sil.py -> reports/m6_sil.json; src/gridmon/c_sil.py)
Golden vectors (all traces, features, labels), full val / test_iid / test_shift and every 10th train record
(`--fast`: the data/fast splits), sanitizer build on the golden vectors, portability checks, memory and
host time. The sealed test splits are read for EQUIVALENCE only (no labels loaded, no accuracy computed).
Acceptance (PROMPT_03 A3): traces/features within golden/README.md and FEATURES.md tolerances; rule labels
>= 99.5 % (target 100 %) with every disagreement and its cause; GBM (a) C walker vs the Python float32 walker
on the SAME C features bit-exact labels and |proba diff| <= 1e-6, (b) end-to-end labels >= 99.5 %.
Results: docs/HANDOFF.md section 2 and reports/m6_sil.json.

## 8. Implementation notes (same method, float32-friendly evaluation; DECISIONS D-055..D-061)
- Unwrapped angle: angU(m) = ang(m) - 2 pi N(m), N(m) = sum of the integer wrap counts
  floor((ang(m) - ang(m-1) + pi)/(2 pi)) — identical in exact arithmetic to the cumulative sum of
  wrapped differences (DSP_SPEC 7), without float32 accumulation (e_ang error 2e-6 rad vs 1.8e-4 tolerance).
- df_raw is computed into the df buffer and averaged in place in descending m (saves a 4 KB buffer).
- Frequencies are carried as deviations: f_ref = 50 + median(df); f_pll - 50 = u/(2 pi) (the PLL phase still
  integrates w = 2 pi 50 + u).
- THD sums 500 terms as 10 partial sums of 50 (smaller float32 error; same sum).
- Medians: insertion sort of a copy (n <= 131); even counts take the mean of the two middle values.

## 9. Known differences from the float64 reference
- **Float32 argmin ties in rho.** m* = first argmin over OBS of |V1|. On flat |V1| (no dip) two OBS samples
  can round to the same float32 |V1| (ulp 1.2e-7 at 1 pu) while float64 still orders them; the first index
  then differs and V2(m*) moves by the noise of V2 (up to ~1e-3 pu), i.e. up to |dV2|/0.01 in rho when the
  denominator is floored. Observed: 2 of 1,750 test_iid records (both non-dip: urms_min_1 >= 0.94; rho is
  only used by the rules inside a dip; GBM labels identical). Reported in m6_sil.json with the diagnosed
  cause; not gated (FEATURES.md unchanged).
- **No-signal records** (v1_ref = 0, e.g. all-zero input) are outside the reference's domain: Python yields
  NaN/inf for |V1|-relative features (and numpy's argmax over all-NaN spectra returns env_mag_freq = 3 Hz);
  the C core flags those features invalid (GM_FLAG_NO_SIGNAL) and the rules then give the same label
  (balanced dip). THD with a zero fundamental likewise -> feature invalid (GM_FLAG_THD_INVALID).
- Argmax-type features (j_sign, env_*_freq, env_*_prom) and masks can differ at float near-ties exactly as
  documented in FEATURES.md (gates) and golden/README.md (masks within 1e-3 deg of the 3 deg detection).

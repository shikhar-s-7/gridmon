# Integrating gridmon into a C2000 inverter controller (M7) — monitor-only

> **Simulation-only (Stage 1).** Everything below was built and tested on a PC (host simulation of the port
> layer); nothing has run on a C2000 or on power hardware. TIDA-01606 (800 V DC nominal) and
> TIDM-HV-1PH-DCAC / TIEVM-HV-1PH-DCAC (380 V DC) are **high-voltage** hardware: any board work only under
> qualified supervision, with isolated debug connections, and only after L3-L4 have passed on a LaunchPad.

## 1. In plain language
The inverter's control software already measures the grid voltages tens of thousands of times per second.
gridmon adds a **listener**: in the fast control interrupt it copies each measurement into its own small
buffer (a few dozen multiplications, nothing else), slows the data down to 5,000 samples per second, and
keeps the last 1.6 seconds. In the slow background part of the program it watches for anything unusual
(a dip, a swell, a phase jump, a frequency change, a wobble of the voltage). When it sees one, it cuts out
one second of voltage around the moment it started, classifies it (seven classes), and publishes a short
report: what happened, when, why (which rule fired), and what the learned model thinks (advisory only).

It **never** changes anything in the control loop: it does not write a control variable, a PWM register, a
protection flag or a setpoint. If gridmon misbehaves, the worst case is a wrong or missing report.

## 2. Monitor-only principle
- Inputs by value only: `gm_port_push(&port, v1, v2, v3)` receives copies of voltages the control law has
  already computed; the port has no pointer to any control variable.
- Outputs: a `gm_telemetry_t` struct handed to the background loop (and from there to SCI/CAN/IPC). The
  application must not feed it back into control or protection (a separate, validated project would be needed).
- The ISR side never waits: if the background falls behind by more than 1.6 s the newest samples are dropped
  and counted (`overruns`); the background then restarts its trigger (`resyncs`).
- The rules label is the **primary** output; the gradient-boosting label is **advisory** (logged with its
  probability, never acted on) — D-050, RESULTS finding 2 (the model degrades under distribution shift).

## 3. Architecture (firmware/c2000/)
| piece | where it runs | what it does |
|---|---|---|
| `gm_port_push()` (gm_port.c) | control ISR at f_in = 20/40/50/100 kHz | calibration trim (REQUIRED, D-052) -> optional LN->LL -> polyphase anti-alias FIR + decimation to exactly 5 kHz -> int16 ring buffer (1.6 s, 48,000 bytes) |
| `gm_port_background()` (gm_port.c) | background loop, low-priority task or CPU2 | trigger at 5 kHz, onset estimate, record placement, copy-out, `gm_process_record`, telemetry |
| `gm_process_record()` (c/src) | called by the background | the M6 core: 37 features, rules (primary), GBM (advisory) |
| gm_port_c2000.c | device glue | where the ISR call goes, CPU-timer timestamps, telemetry sink stub, example config (no driverlib in the portable part) |
| gm_port_fir.c | const tables | FIR taps for each f_in, generated by scripts/gen_c_tables.py (D-054) |

Anti-alias filters (same spec as configs/aa_fir.json: passband >= 1 kHz, >= 40 dB at >= 2.5 kHz, gain 1 at 50 Hz):
| f_in | taps L | decimation D | taps per phase K | stopband | ISR cost per input sample (3 channels) |
|---|---|---|---|---|---|
| 20 kHz | 49 | 4 | 13 | 53.9 dB | 39 FIR MACs + 6 trim/LN mults = 45 (0.90 M/s) |
| 40 kHz | 99 | 8 | 13 | 53.9 dB | 45 (1.80 M/s) |
| 50 kHz | 123 | 10 | 13 | 53.7 dB | 45 (2.25 M/s) |
| 100 kHz | 245 | 20 | 13 | 53.4 dB | 45 (4.50 M/s) |
The polyphase form spreads the work evenly: every input sample costs K = 13 MACs per channel (no burst every
D-th sample); every D-th call additionally rounds three outputs to int16 and stores them. Measured on the host:
the C decimator equals the float64 reference within 0.51 LSB (LSB = 2^-14 pu) at every f_in.

## 4. TIDA-01606 (three-phase, 50 kHz) — integration steps
1. **Where to call it.** In the 50 kHz control ISR, after the ADC results have been converted to per-unit
   voltages and after the control law has run, add one line: `gm_port_push(&gm_port, va, vb, vc);`.
   Initialise once at start-up: `gm_port_init(&gm_port, &cfg, &gm_ctx, gm_record)` with `cfg.f_in_hz = 50000`
   (decimation by 10). [ASSUMED from the TIDA-01606 design: 50 kHz PWM/ISR and TI's SRF software PLL; check
   your SDK version for the ISR name and the voltage variable names.]
2. **LN or LL sensing.** gridmon works on line-to-line voltages in pu of the nominal LL peak. If the board
   senses phase-to-neutral voltages (check the schematic/user guide), pass them in pu of the nominal LN peak
   and set `cfg.input_ln = 1`; the port forms v_ab = (v_a - v_b)/sqrt3 etc. If it senses LL, pass them with
   `input_ln = 0`. (Tested on the host: both modes give the same decimated samples within 2 LSB and the same
   outcome for all 14 stream events.)
3. **Calibration (REQUIRED, D-052).** The rules are calibration-sensitive (RESULTS finding 6: a -2 % gain
   error pushed an oscillation below the 0.90 pu dip level). Per input channel c, measure gain and offset at
   commissioning: (a) with the grid disconnected or the sensing input shorted, average the per-unit reading
   over >= 1 s -> `offset[c]`; (b) apply a known reference voltage (or compare against a calibrated meter at
   nominal grid voltage) and set `gain[c] = true_value / (reading - offset[c])`. Enter both in
   `gm_port_cfg_t`; the port applies `v = gain * (x - offset)` before the filter. Re-check yearly or after
   sensor changes. Target accuracy: better than 0.5 % gain, 0.005 pu offset (the iid training range).
4. **CPU budget.** ISR: 45 MACs + ~20 other operations per call; at 200 MHz with FPU32 this is estimated
   at roughly 100-150 cycles (0.5-0.75 us of the 20 us ISR period, ~3 %) [ASSUMED; measure at L3]. Background:
   the trigger costs ~10 operations per 5 kHz sample plus ~150 per 1 kHz phasor (~0.3 M operations/s);
   a classified record costs ~1.5 M operations (M2 budget: 1.38 M MAC, 24 k transcendental calls), estimated
   20-30 ms at 200 MHz without TMU mapping, maybe ~15 ms with TMU intrinsics [ASSUMED; measure at L3]. The host
   simulation blocks the background for 50 ms per record and still has 0 overruns (the ring buffer covers
   0.6 s of background stall beyond the 1 s record history).
5. **Memory map (C28x 16-bit words, from host sizeof; confirm with the linker map at L2/L3).**
   | object | words | place |
   |---|---|---|
   | gm_port_t (incl. ring 24,000) | ~25,200 | GSx RAM (shared RAM if the background runs on CPU2) |
   | gm_ctx_t | 7,908 | GSx or LSx RAM |
   | record buffer int16 3 x 5000 | 15,000 | GSx RAM |
   | gm_result_t + telemetry | ~200 | any RAM |
   | DSP tables / GBM model / FIR taps (const) | 2,700 / 6,986 / <= 520 (one f_in) | flash (copy to RAM for speed) |
   | code | see reports/m7_c28x_size.json (L2, run locally) | flash |
   F28379D (data sheet): 1 MB flash per CPU and 204 KB RAM in total, of which GS0-GS15 = 64 K words are
   shared between CPU1 and CPU2. The ~48 K words of RAM above fit, but plan them with the existing firmware's
   memory map (the control firmware already uses part of GSx RAM).
6. **Telemetry.** One `gm_telemetry_t` per classified record: sequence number, trigger and record timestamps
   (5 kHz sample counter; latch a CPU timer at publish for wall-clock time), trigger cause, rule label/reason
   and onset (primary), GBM label and max probability (advisory), status/flags, health counters (overruns,
   triggers, resyncs, clipped records). Send it over SCI/CAN from the background loop; never from the ISR.

## 5. Trigger and record placement
Trigger thresholds are deliberately **below** the classification thresholds, so the trigger fires early and
the classifier decides: Urms(1/2) outside [0.92, 1.08] pu (rules: 0.90/1.10), |J| > 3 deg (rule: 5 deg),
|f_dft - f_ref| > 0.15 Hz for 100 ms (rule: |df_end| > 0.2 Hz), envelope deviation > 1.5 % with opposite
signs within 0.3 s (oscillation). f_ref follows slow drift (EMA, 1 s) but freezes once the deviation exceeds
0.05 Hz and is re-armed after each hold-off; the sign-alternation test keeps single |V1| steps (hard negatives)
from firing. Hold-off: 1 s after each captured record.
- Exception to "below": the envelope trigger needs a 1.5 % peak deviation while the oscillation rule fires at a
  1.0 % spectral amplitude, so a 1.0-1.5 % oscillation would be classified as oscillation if captured but does
  not trigger by itself (the class in this project has depth >= 2 %; angle-only oscillations rely on the
  |J| trigger). Documented sensitivity gap; Stage 2 may lower it after a false-trigger study.
- Placement: the classifier was trained with the onset at 0.20-0.40 s and assumes the first 0.15 s is
  pre-event, so each record starts 0.28 s before the estimated onset. Fast triggers (Urms, J) estimate the
  onset within a cycle; the frequency trigger back-extrapolates: onset = first exceedance - 0.15 Hz /
  ROCOF_est - 30 ms (ROCOF_est = max |df/dt| over the last 0.2 s); the envelope trigger uses its first
  exceedance - 25 ms. Look-back is limited to 0.72 s (ring 1.6 s).
- Known behaviour: after a frequency event the stream model returns to the pre-event frequency at 0.2 Hz/s
  (assumed secondary control); the trigger captures that recovery as 1-2 extra records, which the rules
  classify as normal. A deployment may merge captures within an event (Stage 2).

## 6. TIDM-HV-1PH-DCAC (single-phase)
One board sees one phase, so the three-phase features (V1/V2, Bollen ratio, three-channel Urms) are not
available: it needs the **Stage 2 single-phase variant** (not built). For the three-board 120 deg setup, do
not split this core across the inverters: run the unchanged three-phase core on a **separate monitor node**
(e.g. a LaunchPad with isolated L-N voltage sensing of all three phases, input_ln = 1, calibrated per channel),
independent of the three inverter controllers, publishing telemetry to the same log.

## 7. Host simulation evidence (reports/m7_port_stream.json, reports/figures/m7_port_stream.png) [SIM]
120 s at 50 kHz, seed 7007, 14 events (2 per class, iid parameters with label margins), 6.65 s gaps each with
hard negatives, SNR 44 dB at 50 kHz + 12-bit ADC, iid gain/offset errors removed by the calibration trim; fed
sample by sample through `gm_port_push`, background every 1 ms and blocked 50 ms after each record:
12/12 events captured (latency: Urms/J 4-15 ms, oscillation 66-114 ms, frequency 181-215 ms), true onset at
0.225-0.288 s of the captured record, rules 12/12 and GBM 12/12 equal to the truth, the 2 normal-class
episodes and all 14 gap hard negatives without a trigger (0 false triggers), 3 secondary captures in
frequency recoveries (classified normal), 0 overruns. This is an integration test (n = 14), not an accuracy result.

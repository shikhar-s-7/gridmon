# LaunchPad PIL template (LAUNCHXL-F28379D) — **UNTESTED**

> Status: written and compiled on the host only (pil_records.c); never built with cl2000 or run on a board.
> Simulation-only records. The LaunchPad is low-voltage; nothing here connects to a power stage.

Purpose (validation ladder L3, docs/VALIDATION.md): run the unchanged C core on the real C28x CPU with three
embedded golden records and show (a) the same rule label/reason and GBM label as the host build (L1),
(b) the feature deviation from L1 (TMU/relaxed float mode may change the last bits), (c) the cycle count per
record.

## Files
- `main.c` — CPU1 program: init, SCI-A at 115200 8N1, CPU Timer 1 cycle measurement, `gm_process_record` on
  each record, prints one line per record and `ALL PASS` / `SOME FAILED`.
- `pil_records.{h,c}` — GENERATED by `python scripts/make_pil_records.py`: golden records
  07_val_sag_unbal_0012, 13_val_phase_jump_0020, 16_val_freq_event_0004 (3 x 15,000 int16 = 45,000 words of
  flash) and the host-L1 expected outputs.

## Create the CCS project (Code Composer Studio 12+, C2000Ware 5.x)
1. File > New > CCS Project: target TMS320F28379D, compiler TI C2000 CGT (22.6 LTS or newer), "Empty
   Project (with main.c)". Delete the generated main.c.
2. Copy into the project (or link): `main.c`, `pil_records.c/.h` from this folder; `c/src/*.c`, `c/src/gm_internal.h`,
   `c/include/gridmon.h`, `c/tables/gm_tables.{c,h}`, `c/generated/gm_model_gbm.{c,h}`.
3. From C2000Ware add the driverlib and device support for F2837xD:
   `device/F2837xD_codestartbranch.asm`, `device/device.c`, `device/device.h`, `driverlib/` (or the prebuilt
   `driverlib.lib`), and the linker command file `2837xD_FLASH_lnk_cpu1.cmd`.
4. Include paths: the folders above plus C2000Ware `driverlib/f2837xd/driverlib` and `device_support/.../common/include`.
5. Predefined symbols: `CPU1`, `_FLASH`, `_LAUNCHXL_F28379D` (LaunchPad pin mapping of SCI-A: GPIO 42/43 via the
   XDS100v2 COM port), optionally `GM_ENABLE_GBM=1`.
6. Compiler options (same as scripts/c2000_compile_check.py): `-v28 -ml -mt --float_support=fpu32
   --tmu_support=tmu0 --abi=eabi -O2 --fp_mode=relaxed --c99 --float_operations_allowed=32`.
7. Linker: stack >= 0x400 words; add to the .cmd file a GS-RAM section for the context (7,908 words):
   ```
   ramgs_gridmon : > RAMGS0 | RAMGS1 | RAMGS2, PAGE = 1   /* gm_ctx_t (DATA_SECTION in main.c) */
   ```
   Place `.const` / `.econst` (golden records 45 K words, GBM model ~7 K words, DSP tables ~2.7 K words) in FLASH
   (the default FLASH .cmd does). For speed, the tables may later be copied to RAM.
8. Build, flash, open a terminal on the XDS100 "Application/User UART" COM port at 115200 baud, reset.

## Expected output (from the host L1 build; cycles unknown until L3)
```
gridmon PIL (UNTESTED template): gridmon-core 0.6.0 (model gbm_embedded seed0 sha256 e25501759a5f84fe; tables 17f72797b3f4fbba; gbm on)
ctx words: 7908
07_val_sag_unbal_0012: rule 2 reason 2 gbm 2 cycles <N> max|dfeature| x1e6 <small> PASS
13_val_phase_jump_0020: rule 4 reason 6 gbm 4 cycles <N> max|dfeature| x1e6 <small> PASS
16_val_freq_event_0004: rule 5 reason 7 gbm 5 cycles <N> max|dfeature| x1e6 <small> PASS
ALL PASS
```
(rule/gbm values are class indices: 2 sag_unbal, 4 phase_jump, 5 freq_event; reasons 2 dip_unbalanced,
6 phase_jump, 7 freq_offset.) The C28x `ctx words` is sizeof in 16-bit words; it may differ slightly from the
host value through alignment. Estimated cycles: 4-6 M per record at 200 MHz (20-30 ms) without TMU mapping
(docs/C2000_INTEGRATION.md section 5); a measured value replaces this estimate at L3.

## If it fails
- `FAIL` with correct rule label but a different reason/GBM label, or `max|dfeature|` far above the
  FEATURES.md tolerances: build without `--fp_mode=relaxed` and without TMU (`--tmu_support` removed) to see
  whether the fast math paths cause it; report the numbers back (that is the L3 result).
- Nothing on the terminal: check the COM port and the `_LAUNCHXL_F28379D` symbol (SCI-A pins).

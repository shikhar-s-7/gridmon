# gridmon — grid-event monitor for battery-inverter voltage records

> **Simulation-only research prototype. Not validated on measured data. Not for protection or control.**

gridmon recognises grid events — balanced and unbalanced voltage sags, swells, phase jumps, frequency events,
low-frequency oscillations, or normal operation — in triggered 1 s three-phase line-to-line voltage records at the
AC terminals of a battery energy storage system's power conversion system (PCS). It compares, on the same 37
physics features, a transparent standards-based rule set with a small gradient-boosting model (13.6 KB), and it
ships one portable C99 float32 core that reproduces the Python reference on a PC, compiles for TI C2000
microcontrollers as a monitor-only module, and runs in the browser as WebAssembly.

**Headline [SIM]:** on test data drawn like the training data, the rules and the tree model are equally good.
Under a distribution shift (more noise, calibration error, an unseen transient) the rules barely move while the
tree model becomes significantly worse, mostly by missing phase jumps and flagging normal records (table below) —
so the rules label is the primary output of the C core and the model is advisory.

## Architecture
```
 Python reference (src/gridmon)        generator -> DSP (DSP_SPEC) -> 37 features -> rules | GBM      [frozen, M4]
        |  golden vectors, SIL equivalence (reports/m6_sil.json)
        v
 C99 float32 core (c/)                 no malloc, no static RAM, 15.8 KB state, constants generated (D-054)
        |-> PC: shared library + ctypes SIL, CLI, sanitizers          (L1 done)
        |-> TI C2000: firmware/c2000 port layer, monitor-only          (L2 compile done; L3 PIL template ready)
        '-> Browser: WebAssembly (web/), same sources                  (equivalence checked in Node)
```

## Quickstart
```
python3.12 -m venv .venv                       # Windows: py -3.12 -m venv .venv  (then .venv\Scripts\python)
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip install -e .
.venv/bin/python scripts/run_all.py --fast     # data, rules, golden vectors, GBM, sealed evaluation (fast subset, ~2 min)
.venv/bin/python -m pytest                     # uses data/ if present, else data/fast
.venv/bin/python scripts/build_c.py            # C core for the PC (cc/gcc/clang, or python -m ziglang cc)
.venv/bin/python scripts/run_sil.py --fast     # C core vs Python
.venv/bin/python scripts/build_site.py         # website -> web/dist (needs python -m pip install ziglang)
python -m http.server -d web/dist 8000         # preview at http://localhost:8000
```
Full data: `scripts/run_all.py` (about 10 minutes on 4 cores). The C2000 compile check needs TI's compiler on your
machine: docs/C2000_BUILD.md. Reproducibility record: docs/REPRODUCIBILITY.md.

## Limitations
Synthetic data from this project's own generator (the shift is one designed nuisance configuration); strong-grid
assumption without converter dynamics; single-label records; no measured data and no hardware run yet. Details:
reports/RESULTS.md (sections 10-11), docs/VALIDATION.md, docs/STAGE2_PLAN.md.
